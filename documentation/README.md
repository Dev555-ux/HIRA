# documentation/

**Purpose**: Human-readable knowledge about the product and system that isn't code — the stuff a new engineer, advisor, or future-you needs to get oriented without reading every file.

**Will eventually contain**:
- Architecture overview (system diagram, how WhatsApp → AI → Calendar/DB flow works)
- API contracts/specs for internal services
- Onboarding guide for new contributors
- Glossary of domain terms (Assisted Mode, Autonomous Mode, escalation, knowledge base, etc.)
- Customer-facing setup guides (how a business connects WhatsApp, uploads FAQs, etc.)

**Why it exists**: Code explains *how* something works; this folder explains *what* and *why* at a level that survives refactors. Without it, onboarding and cross-functional handoffs (e.g., explaining the system to a non-technical cofounder or investor) rely on tribal knowledge.
